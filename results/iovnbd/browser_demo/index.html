Browser ONNX runtime compatibility — validated

  • Runtime: onnxruntime-web@1.18.0, execution provider wasm (same as frontend/mobile.html)
  • Model opset: ai.onnx 17
  • Input: imu_window — shape [1, 50, 6], float32
  • Output: speed_mps — shape [1, 1], float32 (de-normalization already baked into the graph — no caller-side denorm needed)
  • Real session creation and real inference both succeed on this exact file
  • Measured latency in the compatibility test environment: ~8.9 ms — this is a measured-test-environment number, not a phone performance claim

Live phone integration — NOT VALIDATED

Browser ONNX execution is validated (above). Live phone sensor feature mapping is not, for two specific, unresolved reasons — nothing here is guessed or assumed:

  • Gravity inclusion. The model was trained on IO-VNBD's raw smartphone accelerometer, which includes gravity (its accel_z channel has a trained mean of ~9.85 m/s²). frontend/mobile.html's live IMU.ax/ay/az are deliberately gravity-compensated for its own EKF/dead-reckoning math — a different physical quantity, not a relabeling.
  • Axis/frame correspondence. IO-VNBD's own phone-mounting axis convention is not established in this dataset (data/iovnbd.py documents this as an open item), and frontend/mobile.html treats phone orientation as arbitrary/unknown, auto-detecting its own forward axis per session rather than assuming a fixed frame. There is no verified correspondence between IO-VNBD's x/y/z and a live phone's current orientation.

Because of this, no live phone speed number is claimed anywhere — this page shows the model's real behavior on real recorded data only, and makes no claim that this model improves real-world navigation accuracy on a phone.

NAVDRIFT-0 production navigation (EKF, ZUPT, NHC, DriftFormer, GNSS handling, RoadGraph, LiveHMM, tunnel detector, wake lock, native code) is untouched by this page and by the model it demonstrates. This page is a standalone artifact under results/iovnbd/browser_demo/ and is not referenced by, or loaded from, frontend/mobile.html.

If opened via file://, this page's fetch() calls for the model and sample data may be blocked by the browser — serve it from the repository root instead, e.g. python -m http.server, then open /results/iovnbd/browser_demo/index.html.
